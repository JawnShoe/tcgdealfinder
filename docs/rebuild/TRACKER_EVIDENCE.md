## Legacy Feature Recovery Mapping

This section maps capabilities from the **Decision Tagging Pass – Legacy Feature Recovery List** to rebuild state.

**Definitions:**

- **Recovery List Status** = verbatim from Decision Tagging Pass (Partial / Missing / Intentionally Dropped)
- **Evidence** = PR numbers or "None"
- **Parity Reviewed** = Yes / No (default No unless explicitly reviewed)

### Rules

A capability may only be marked **Recovered** when:

1. Evidence exists in TRACKER_EVIDENCE.md
2. A parity review decision has been explicitly recorded

**Shipping code ≠ recovered.** "Partial" is allowed indefinitely until parity is reviewed or scope is changed.

### Parity Review Method

**Parity review means:** legacy capability intent verified against current rebuild behavior.

- Legacy artifacts are used only to define intent + expectations, not implementation.
- A capability can be marked **Recovered** only if:
  1. Parity Verdict is **Meets** or **Exceeds**, and
  2. Evidence PR(s) exist in TRACKER_EVIDENCE.md

**Reference artifacts for parity review:**

- `docs/surfaces.md` — homepage/table column expectations, interaction patterns
- `docs/archive/ui-baseline.md` — formatting/hierarchy rules, column alignment
- `docs/archive/design/DESIGN_AUDIT_2025-01.md` — table/trust critique, visual hierarchy
- `docs/archive/DECISIONS.md` — interaction decisions, seller trust display
- `docs/archive/rebaseline/modules/M05_SCORING_CONFIDENCE.md` — confidence algorithm expectations

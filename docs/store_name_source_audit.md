## B) Findings per Source

1. **Sell Stores API `getStore`**
   - Requires seller-managed OAuth with `sell.stores.read`; documentation states API is designed for managing *your own* eBay Store.
   - eBay policy prohibits pulling store metadata for other sellers without delegated consent.
   - Practical effect: no app-level token can retrieve external seller storefront names.
2. **Trading API `GetStore`**
   - Legacy Auth’n token flow; the token is generated by the seller (via Redirect URL / Sign-In).
   - Without the seller’s token, the call returns `Auth token is invalid` or `This call is restricted to the authentication token owner`.
   - Therefore unusable for arbitrary sellers.
3. **Trading API `GetUser`**
   - Public info available with AppID only, but `Storefront` node is returned only when requesting the authenticated user (per docs and testing). Third-party lookups omit the store data entirely even though username/feedback is available.
   - Conclusion: cannot harvest store display names for arbitrary accounts.
4. **Trading API `GetItem`**
   - Historically exposed `Seller.Storefront.StoreName/StoreURL`; now flagged as deprecated. API reference states “value removed by policy for non-owner callers.”
   - Sample output from existing listings in our DB shows `storefront` null – matches current behavior.
5. **Buy Browse API seller payload**
   - Normalized output only exposes seller username, feedback score, feedback percentage. No storefront fields documented or observed.
   - Therefore cannot satisfy the requirement.

## C) Mini Experiment Results

| Attempt | Endpoint | Request Shape | Result |
| --- | --- | --- | --- |
| Sell Stores `getStore` | REST (seller scope) | Requires seller OAuth; we only have app credentials | BLOCKED (needs seller consent) |
| Trading `GetStore` | SOAP | Requires seller Auth’n token | BLOCKED |
| Trading `GetUser` (`ANDYCARDS`) | SOAP | App-level request returns profile but no `Storefront` node | BLOCKED – response lacks store info |
| Trading `GetItem` (`ANDYCARDS` listing) | SOAP | Response includes `Seller.Storefront` node set to null | Fails – no store name when caller is not seller |
| Browse API `/item/{id}` | REST | Returned `seller.username`/feedback only | Confirmed: no store name field |

## D) Recommendation

**NO-GO** – There is no supported public API that returns another seller’s storefront display name without that seller’s explicit consent/token. All official sources either (a) require seller-auth tokens (Sell Stores, Trading `GetStore`, `GetUser`), or (b) no longer expose storefront data to third parties (`GetItem`, Browse). Continuing to rely on the deprecated Shopping API is unsustainable and non-compliant.

## E) Integration Plan (Not Applicable)

Since no GO path exists, no integration plan is proposed. Any future effort must involve either:

1. Securing explicit seller consent and tokens (out of scope for public deal aggregation), or
2. Identifying a new eBay-provided endpoint that is explicitly documented for third-party storefront lookup (none available as of 2025-12-20).
